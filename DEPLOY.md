# Deploying FlowForge on Render + Supabase (free)

FlowForge runs as **one Render web service** (API, workflow runner and website
together) with a **Supabase Postgres** database. There's no Redis: the job queue
is stored in Postgres. Emails go through **Brevo**, because Render's free plan
blocks SMTP (Gmail App Passwords don't work there).

Free plans change often; check each provider's current limits.

## 1. Database: Supabase

1. Create a project at [supabase.com](https://supabase.com). Choose a strong database
   password with only letters and digits (other characters must be URL-encoded).
2. Click **Connect** and copy the **Session pooler** connection string. Don't use
   the "Direct connection" one: it's IPv6-only and Render can't reach it.
   It looks like:
   `postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`
3. Add `?sslmode=require&connection_limit=5` to the end. This is your `DATABASE_URL`.
4. Recommended: FlowForge doesn't use Supabase's auto-generated Data API. Turn it
   off in the project's API / Data API settings so the tables FlowForge creates
   (users, saved connections...) can't be reached through it.

FlowForge creates its tables itself on every start (`prisma migrate deploy`), plus a
`pgboss` schema for the job queue.

## 2. Email: Brevo

1. Create a free account at [brevo.com](https://www.brevo.com).
2. **Senders, domains & dedicated IPs → Senders**: add the address emails should come
   from and verify it. For the best delivery, use an address on your own domain and
   authenticate that domain in Brevo (Gmail/Yahoo addresses often land in spam).
3. **Settings → SMTP & API → API keys**: create an API key.

## 3. Secrets

Generate `ENCRYPTION_KEY` on your computer:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**Save it somewhere safe** (a password manager). If it's lost or changed, saved
passwords and connection strings in FlowForge can no longer be decrypted.
`JWT_SECRET` is generated by Render automatically.

## 4. Render

1. Push this repository to GitHub/GitLab.
2. In Render: **New → Blueprint**, pick the repository. Render reads `render.yaml`
   and asks for:

   | Setting | Value |
   |---|---|
   | `DATABASE_URL` | The Supabase string from step 1 (with `?sslmode=require&connection_limit=5`) |
   | `ENCRYPTION_KEY` | The value from step 3 |
   | `BREVO_API_KEY` | From step 2 |
   | `EMAIL_FROM` | Your verified sender, e.g. `FlowForge <hello@yourdomain.com>` |
   | `GEMINI_API_KEY` | For the AI step (optional) |

3. Deploy. The first build takes a few minutes. The log should show
   `[Runner] Ready to run workflows` and `[Mailer] Sign-up emails will be sent via Brevo`.
4. Open `https://<your-service>.onrender.com`, create an account and check the
   confirmation email arrives.

Webhook URLs look like `https://<your-service>.onrender.com/api/v1/wh/<workflow-id>`
(the editor shows the exact one).

### Custom domain

Add it in Render (Settings → Custom Domains), then set `PUBLIC_URL` to it, e.g.
`https://flowforge.yourdomain.com`.

## Free plan limits to know

- **Render sleeps after ~15 minutes without traffic.** While asleep, schedules don't
  run, and the first request (or webhook) waits about a minute while it wakes up.
  To keep it awake, have a free uptime monitor (UptimeRobot, cron-job.org...) call
  `https://<your-service>.onrender.com/api/health` every 10 minutes. Render's free
  hours cover one service running all month. The health check also touches the
  database, which keeps the Supabase project from being paused for inactivity.
- **Render free has 512 MB of memory.** Fine for small use.
- **Brevo free sends up to 300 emails/day** (all FlowForge emails combined).
- **Supabase free** includes 500 MB of database storage. Old run history can be
  deleted from the dashboard if it grows.

## Running elsewhere

The same image runs anywhere Docker does: fill in `.env` (see `.env.example`) and
run `docker compose up --build -d`, then open http://localhost:3000.
